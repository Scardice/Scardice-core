# Changelog

## Unreleased

### Added

- Manual backups run as single-flight background jobs with authenticated status polling, real stage/file progress, detailed failure feedback, and WebUI recovery after navigation or a lost admission response.
- Plugins can subscribe to native adapter events with `onAdapterEvent(ctx, event)` and an optional object filter: notice-only by default, explicit event lists or `"all"`, and strictly typed top-level predicates. Unknown OneBot notifications retain their full JSON instead of being rejected solely for their event type; conversation-free events use `ctx === null`, follow extension lifecycle fences, and have bounded delivery diagnostics.
- Added `seal.adapter.callApi`, `callApiRaw`, `enqueueApi`, `enqueueApiRaw`, and `getOperation`. Direct calls preserve async caller ownership and complete protocol responses; raw calls preserve numeric spellings and adapter-owned echo correlation. Queued calls use the existing encrypted transactional outbox, classify uncertain non-idempotent outcomes without unsafe retries, and do not synthesize message-send hooks. Both Goja and QuickJS receive native JSON objects/arrays.
- Account settings now show each endpoint's live diagnostic entries, severity and counters, with refresh, retry and empty states. Runtime counters reset when the instance restarts.
- The command-test sandbox supports separate test users and groups, configurable member roles, and CQ mentions (`[CQ:at,qq=1001]` maps to `UI:1001`). Typing `@` opens searchable avatar/name/ID suggestions; selection inserts the stable-ID CQ code, while chat bubbles show the nickname. Desktop and mobile layouts support the same workflow.
- The local execution API accepts validated UI sandbox identities and applies its short send cooldown per conversation. UI adapter bot replies retain the actual group ID in outgoing-message hooks.
- Uploading a brand-new JavaScript plugin loads it into the running runtime without a full reload. The VM, resident plugin state and every other plugin's commands stay untouched, user-disabled plugins are only registered, and plugins previously blocked by a missing `@depends` dependency are loaded in dependency order once it arrives. Updating or overwriting a loaded plugin, a plugin whose name is already taken, a reload in progress, and disabled JS support still require the manual reload. `/sd-api/js/upload` now reports `incremental`, `needReload`, the loaded plugins and any rejection reasons, and the plugin page only asks for a reload when one is needed. Partial disable/delete/update are tracked as `TODO(局部重载)` in the code.
- Pure OneBot now handles the notices and requests the removed legacy adapter used to handle, through the durable inbox: pokes, members joining, the bot joining, being removed from, leaving or losing a disbanded group, the bot being muted, new friends, friend requests, and group invitations. Core applies the existing verification question, blacklist, trust-only and refuse-invite rules, reports each request to the notice targets, and answers it through the outbox with the new `answer-request` action, so a request is answered at most once even when the protocol end redelivers it. Friend requests honour the endpoint's `friendRequestPolicy`: `accept` (default) applies the rules, `ignore` and `manual` only report, and `deny` rejects. The mute notice now reports seconds instead of a raw duration count.
- Outbound effects can be delayed with `NotBefore` instead of making a callback sleep: the bot's welcome after joining a group waits the legacy ~4 s and a new friend's welcome ~5 s, and notices raised inside a callback are staged in its transaction, spaced one second apart, rather than sent by a racing goroutine.
- Pure OneBot events now carry display names. Before an event is handed to Core the runtime makes a bounded (3 s), best-effort `get_group_info` / `get_group_member_info` / `get_stranger_info` lookup; a failed or slow lookup only leaves the name empty and never delays or drops the event. Message senders are named from the payload's group card or nickname. Core remembers names without letting an empty one overwrite a known one, so join reports, invite reports and new players show a name instead of a UID or "unknown", and the bot no longer waits 2 s for a group name after joining.
- Core can ask a running endpoint read-only questions through `adapterapi.QueryRuntime` and `endpoint.Supervisor.Query` (generation-fenced like actions, never persisted or retried). The first query is a group member's role, and the pure OneBot runtime answers it with an uncached `get_group_member_info`.
- Per-plugin allocation sampling. The JS engine reports every outermost plugin invocation to a `jsengine.InvocationObserver` (goja event loops; nested work such as Promise continuations drained inside a callback stays in that callback's window), and `Dice.JSAllocSampler()` attributes the `TotalAlloc` delta of sampled invocations to the owning plugin (script file and name, via the existing execution context) in three phases: `load` (evaluating the entry script), `run` (callbacks the host delivers: commands, message hooks, tasks) and `async` (timers, Promise reactions and host-service completions such as `fetch` or filesystem results). Host completions re-enter the realm under a context marked `Completion`, so a queued callback and a finished fetch are not confused. Sampling reads `ReadMemStats` (the cheaper `runtime/metrics` counter cannot see allocations below a span), so it measures loading always and otherwise the first 16 invocations per plugin and phase, then one in 16, capped at 100 per second. The Go heap counter is process-wide: a sample includes the Go-side work host APIs do on the plugin's behalf and anything other goroutines allocate meanwhile. Each sample records whether it overlapped another JS invocation; exclusive samples rule that out but not allocation by non-JS goroutines. `Snapshot()` returns calls, samples and bytes per plugin and phase. QuickJS runtimes and isolated goja realms are not observed yet.
- Per-plugin live heap estimates. The Scardice goja fork gains `Runtime.SetAllocationTracker`, which reports every ordinary object, array and `ArrayBuffer` a runtime creates and every one that grows large later (element storage of 1024+ elements, including literals, spread, `splice` and `unshift`; 1024+ properties or sparse items; new buffer data), and `Object.ApproximateSize`, which estimates what an object owns directly (property table, elements, buffer bytes, directly held strings and boxed numbers, using a stratified random sample above 1024 elements). `Dice.JSHeapTracker()` attaches to every goja runtime, charges allocations to the plugin whose invocation made them, tracks objects of 64 KiB or more one by one and samples smaller ones with probability 1/64 through weak pointers, and every 15 s sweeps the survivors on the event loop to publish live object counts and bytes per plugin and kind. Records of collected objects are pruned while allocating and storage left from a past peak is released, so heavy churn does not accumulate them. In the pressure test the tracker added 0.1% to a 244 MiB plugin heap, and its estimate was within 1% of the retained bytes. `/sd-api/js/list` reports `memory` per running plugin (`ok`, `pending` before the first sweep, `unsupported` for QuickJS), and the plugin page shows it in its own column and breaks it down in the plugin details. Map/Set, closures and host objects are not counted yet; isolated realms and QuickJS have no allocation hooks (`TODO(插件内存)`).
- Group log gap recovery now uses the pure OneBot history query and durable inbox. A batch of at most five missing messages follows normal command processing; larger batches only append logs on a separate inbox lane, without command/plugin hooks, player mutations or per-message reminders. Recovery starts after the triggering callback commits, skips the bot's messages, retains provider message identity for deduplication, and reports committed outcomes rather than submissions. Dice masters can run `.log check <afterSeq> <beforeSeq>` to compare up to 1000 sequence positions against the active log before applying the same rule.

### Changed

- Tests are grouped by behavior with shared queue, callback, backup, and browser fixtures. The WebUI provides a serial `pnpm test` entrypoint, and the native corpus validates runtime-generated exception stacks.
- Core builds now require Go 1.27.3. CI and `task install` pin golangci-lint v2.15.0; Sonic v1.15.3 and loader v0.5.2 preserve native JSON processing on Go 1.27.
- EC JWK/raw-key conversion and ECDH use current Go standard-library key APIs. EC private JWKs must match their declared public points; legacy RSAES-PKCS1-v1_5 support remains available for existing plugin API compatibility.
- The legacy `PlatformAdapterOnebot` (and its helper constructor `NewOnebotConnItem`) is removed. OneBot endpoints run only through the pure runtime; the image asset URL derivation, ID helpers and friend-request/blacklist rules moved to their own files.
- Goja RSAES-PKCS1-v1_5 encryption, decryption, key wrapping, and unwrapping emit per-call WARN deprecation logs with the calling plugin, source, and RSA-OAEP/SHA-256 migration guidance, without logging cryptographic data. CommonJS plugins can require the runtime's `crypto` module; the API reference includes an executable OAEP migration example and ciphertext compatibility limits.
- The JavaScript engine moves from goja `8b74ce4` (2026-02) to upstream `6b6a90e` (2026-10), pinned through the `Scardice/goja` fork. It brings regexp named groups and `\p{…}` with the `u` flag, UTF-16-correct string splitting and comparison, `Promise.withResolvers`/`Promise.try`, `Object.groupBy`, ES2025 Set methods and Iterator helpers, `for await`, `Uint8Array.fromHex`/`fromBase64`, many spec fixes, and lazy string concatenation (300 000 `s += "ab"` steps drop from about 22 s to 0.14 s). The parser now limits nesting to 10 000 levels and treats `<!--` as a comment. The only intentional divergence from upstream is that host functions returning a nil Go slice or map still reach plugins as an empty array or object; upstream now delivers `null`, which would break plugins that read `.length` of such a result.

### Performance

- Compact private fields in message objects, character attribute items, and HostBridge registry entries without changing exported field order, serialization tags, or ABI types. On Linux/amd64 with Go 1.27.3, message and attribute-item heap allocations drop from 288 to 256 bytes and 176 to 160 bytes respectively; HostBridge map values shrink from 88 to 80 bytes.
- Registering a plugin's extension or config no longer replays the whole extension-state event stream. Each registration used to load the stream two or three times, and each replay cloned and revalidated the entire state for every event, which is quadratic: loading about 100 real plugins allocated 22 GB on a fresh database and 36 GB on a reload, and took 24-32 s. Stored history is now applied in place and validated once, and the Dice keeps an `extensionstate.SnapshotCache` that continues from the last replayed state, trusting it only while the stream still holds the event it ended on (same id and checksum), otherwise replaying in full. Newly appended events keep the strict per-event validation, and callers still get an independent copy of the state. With the same plugins the first load takes 4.9 s (2.5 GB), a reload 2.1 s and a restart on the existing database 2.0 s (1.5 GB, mostly the one 7 MB tokenizer plugin).
- Durable inbox and outbox scheduling uses indexed, transactionally maintained active lane heads. Ready-time ordering avoids lane-local sequence bias, while payload-presence indexes skip already-scrubbed history and future-due heads without backlog-wide negative scans.
- Local event-store index keys are validated and read once, while rotatable encryption roots and their `current` pointer use a short concurrent TTL cache; hot plugin KV and idempotency HMAC paths no longer re-stat and reread key files.
- Custom-reply `exprTrue` conditions reuse a bounded DiceScript bytecode cache without caching results, and completed message callbacks release their per-message VM, parser, deck and random-source references.
- Goja async-context propagation now keeps distinct `setTimeout`, `setInterval` and `setImmediate` bindings. Delayed jobs retain their delay, arguments and cancellation handles instead of becoming immediate recursive loops that repeatedly write plugin storage.

- Long-message pagination now scans only to the next visible-text boundary, avoids repeatedly stripping CQ codes and compiling newline regexes, and preserves CQ, UTF-8 and newline pagination behavior.
- Group configuration restores now decode extension names and ordinary fields together, retaining shared extension objects and missing-extension placeholders without a second JSON pass.
- Sensitive-word matching walks UTF-8 directly instead of allocating a full rune copy, preserving shortest-prefix matches, overlapping starts and invalid-UTF-8 handling.
- Full readiness validation reuses transaction-locked readiness and projection-control rows and borrows internal manifest buffers; public reads retain owned buffers, full hashes and root-revocation checks.
- Complete encryption-root reference checks execute as one bounded-result SQL statement while preserving all seven ciphertext predicates and each branch's DISTINCT/collation semantics.
- Durable queues share one independent idle probe per queue and broadcast committed work to all existing workers; callbacks and sends retain four-way concurrency, lane/lease rules and the 500 ms fallback ceiling. Persistent probe errors back off without waking every worker, and new work resets the backoff.
- Attribute startup reads use bounded, Dice-scoped projection pages fenced by generation, live terminal and privacy revision. Ordinary character metadata lists remain a single consistent transaction, avoiding new conflicts from unrelated message commits.
- Attribute cache generations now reclaim inactive ID/group slots without ABA reuse, reject stale retained objects and decrypted results, and pin saves against eviction.
- Concurrent cold attribute reads share one load per generation, while invalidation lets new requests bypass stale in-flight reads. Full startup validation and default prewarming remain enabled.
- Pending automatic-quit markers are pruned only after expiration by the existing housekeeping ticker, using pointer-checked deletion so a replacement marker is not removed.

### Fixed

- Script-list responses reference script metadata directly, preserving runtime mutex ownership and the existing flat JSON fields.
- Backup snapshots use hidden staging on the backup filesystem, with complete archives published after close and sync. The WebUI tracks accepted tasks through their terminal result and refreshes the archive list after completion.
- Home activity headings retain their full height above the scrollable list; source IP highlights fit their contents and wrap on narrow screens.
- Adapter passthrough calls and event hooks apply the configured censor mode at admission. Object and raw JSON requests share checks for nested text, message segments, CQ parameters and JSON cards. Actor-based moderation uses the originating message sender and independently committed notifications; global and opaque-event scopes use content admission checks.
- Pure OneBot custom replies using `forward(...)` preserve structured nodes through durable outbound effects, run configured outbound censor checks against the native request envelope, validate echo-expanded request bounds before admission, retain provider message IDs, and dispatch with native group/private forward actions.
- Goja native `await` and Promise continuations retain their originating plugin, message and transaction instead of inheriting the resolver's context. Context-bearing event hooks and command solves wait for their returned Promises; reentrant outgoing hooks join message completion without blocking the JS owner. Post-commit hooks retain separate best-effort scopes.
- Invocation cancellation reaches Goja `fetch` requests, stops pending hook/command waits, and revokes late callbacks. Promise observers release their host payloads on cancellation or runtime close; stopped generations cannot turn missing context metadata into standalone storage authority. Public JS callback names and native Go signatures remain unchanged.
- Endpoint diagnostics now include the active runtime's diagnostic snapshot, including OneBot reconnect attempts and rejected connections. Previously the management API returned only descriptor diagnostics; stopped or replaced generations are not queried.
- The bot no longer goes silent for good when the OneBot protocol end disconnects. The pure OneBot runtime used to report a failure and exit on any disconnect, and nothing restarted it: it stayed `stopped` with desired state `enabled` until someone pressed relogin, which happened twice in production on 2026-10-28 (after a host reboot and after a protocol configuration change). As a client it now keeps its generation and redials with exponential backoff (1 s up to 1 min), including when the protocol end is not up yet at startup; as a reverse server it keeps listening. An outage is reported once as `failed` and the reconnection as `connected`, both logged to `adapter.log`; reconnect attempts and rejected connections are counted in the runtime diagnostics. An unauthorized reverse connection is now refused on its own instead of taking the endpoint down.
- The endpoint lifecycle sink records every state change of a long-lived runtime. Its command IDs were derived from the runtime and state alone, so a runtime's second `connected` was replayed as the first and dropped, and its second `failed` was rejected as a conflicting command. IDs now include the aggregate version read, and repeated observations of an unchanged state are skipped unless an operation is in progress.
- A group the bot has no record of is switched on by its first message again, as before durable callbacks. The callback projected the empty recorded state (switched off) before the session's auto-activation could run, so every group first seen since the migration was recorded as off and ignored commands (19 groups in production). Groups switched on or off from the WebUI (`/group/set_one`) are now recorded in the event store; the switch used to change only the in-memory group, which the next message replaced with the recorded state.
- Plugin settings of the template (string list) type can be saved again from the WebUI and `/js/set_config`. With the event store the value arrives as a JSON list, which the durable config path rejected as `extensionstate: invalid config value` because it accepted only a Go `[]string`; plain and sensitive (encrypted) template settings now take any list of strings.
- Recovered log entries read in their original order even within the same second. Reads use a total `(time, sequence anchor, entry ID)` order, and replies to recovered commands retain their trigger's time and sequence. Log start/resume persists a sequence baseline; recovery never reaches into the paused interval or an earlier session, and in-memory tracking and the recovery lock survive callback projection replacement.
- Hidden rolls (`.rh`, `.rah`, ...) and notices raised inside a message callback reach their target again. A callback's outputs are bound to the privacy subject of the message it handles, but a prepared outbound effect is keyed to its target conversation, so anything addressed elsewhere (the roll result sent to the sender's private chat, a notice to the owner's group) was rejected as `invalid metadata`, while the "发给(…)" line had already been logged as if it were sent. This has been the case since durable outbound was enabled on 2026-10-23: of 27 hidden-roll private messages only the group acknowledgment ever reached the protocol. Effects and their stream events now inherit the callback's subject wherever they are addressed, so a purge of the message's subject still reaches everything derived from it.
- A stopped or crashed process no longer wedges the outbound queue. An effect that was dispatched but whose outcome was never recorded is turned into an `ambiguous` outcome once its lease expires, and that step ran every claim before any new work; with a projection registered (always, in production) it failed every time with `eventstore: lock event sequence failed`, because the transaction handle returned by `Set` kept the conditions of the previous query and the sequence lookup asked for an aggregate type on the wrong table. One such row therefore stalled all outbound messages, retried over a thousand times a second, until it was resolved by hand. The handle is now a clean session; the existing tests missed it because none combined an outbound source stream with a registered projector.
- The projection generation is attached to the transaction handle in one place (`withProjectionGeneration`) for live commits, outbox settlement, projection rebuilds and publication, so no projector or later query can inherit conditions left on a handle by an earlier one. This is the same trap that stalled the outbound queue, closed at the other three sites where it was latent.
- Removed the data race between consecutive commands from the same player (seen as intermittent `-race` failures of the `.ob` tests). Every command wrote `Player.UpdatedAtTime` without synchronization, and nothing ever read it; the group's atomic `MarkDirty`, which each of those writes was already followed by, is what drives persistence. The field and its 20 writes are gone.
- `.log end` no longer crashes the process. The log is uploaded in a background goroutine after the command returns, but it reported the result through the command's message context, which is released by then; `VarSetValue` panics on a released context and nothing recovers a goroutine, so the whole bot exited with `panic: context canceled`, and even without the panic the upload link could not have been sent. The upload now reports through a detached context (`MsgContext.detach`) built for the same endpoint and sender, and a failure while reporting is logged instead of fatal.
- Other background work that outlived its command had the same flaw and now uses the same detached reporting: the delayed `.master relogin` and the `.master checkupdate` upgrade no longer lose their follow-up replies (their actual work uses stable references and never depended on the released context), and `ctx.Notice` / `NoticeCrossPlatform` send each notice from a context of its own instead of the command's, so a notice raised just before the command returns is no longer dropped.
- A reply the durable outbox refuses is now logged as `回复未能发出` with its target. The "发给(…)" log line is written before the send is attempted, and a refusal used to vanish silently, which made lost messages look sent.
- Durable endpoint unavailability errors now retain the failing gate and wrapped cause across resolver, lifecycle, lane-signature and digest checks, making reply-admission failures diagnosable from the emitted error.
- OneBot runtime identity observations persist the provider nickname as the endpoint display name; account cards prefer the configured nickname, then runtime display name, then endpoint ID.
- `.dismiss` and the log-upload group-role check work for pure OneBot endpoints again: the bot's own role is queried from the protocol end (uncached), so a group owner still gets the confirmation code and a plain member can leave at once. A failed, missing or silent (5 s) query keeps the existing safe-confirmation behaviour instead of guessing.
- Pure OneBot handles the protocol's own forms of three notices: a disbanded group arrives as `group_dismiss` (owner in `user_id`) and now counts as the bot losing the group; a whole-group mute (`group_ban` with `user_id` 0) is ignored instead of being rejected as malformed; a permanent mute (`duration` -1) is reported as permanent instead of 0 seconds, and a zero-length ban is no longer treated as a mute.
- `FormData.getAll()`, `keys()`, `values()` and `entries()` return empty arrays instead of a Go nil when the form has no matching entries.
- Invalid numeric ban ranks are reported as integers instead of quoted Unicode code points, satisfying Go 1.27's printf checks without changing rank validation.
- Native UTF-8 conversions preserve empty strings and trailing NUL bytes in both exported values and host-call arguments. QuickJS accepts zero-length sizing requests, and the Echo ABI fixture returns JavaScript `undefined` for absent properties.
- Retained JavaScript context RNG methods no longer race message cleanup. Random-cache access and cloning share the cleanup lock, and legacy V1 evaluation captures its random source without unsynchronized field reads.
- Message-preprocess callbacks propagate runtime export failures instead of silently treating them as absent values; JavaScript null and unsupported non-primitive results retain their no-op behavior.
- API SQLite fixtures run without CGO, native-runtime package tests isolate externally configured providers, and UI archive tests measure their cooldown from the completed request.
- SQLite-backed callback lease and migration-deadline regressions use deterministic clocks without relaxing their deadlines. Asynchronous cleanup checks wait for the completion fence instead of treating admission revocation as completed cleanup.
- SQLite backups bind snapshot destinations as parameters, and legacy log inspection retains row-close errors while releasing database resources on failure.

- Callback outbox effects preserve emission order within each lane, including repeated identical replies. Each send invocation has its own operation identity; retrying an already-prepared request retains its existing identity.
- Durable callback admission now covers Inbox claiming, aggregate snapshot loading, execution, commit, and post-commit publication. Concurrent endpoints sharing group/player state no longer execute against snapshots loaded before the previous callback commits.
- Public plugin `storageSet`, `storageGet`, and `storageList` use the calling runtime's callback transaction, including cross-plugin storage access. Message-bound timers and captured/delegated contexts cannot send or persist after the callback closes.
- Goja message callbacks share one deadline across queue waiting, synchronous JavaScript, and Promise waiting. Cancellation interrupts JavaScript without leaking the interrupt into the next invocation. Native runtime queue waits are cancellable, and expired native context tokens stay revoked instead of becoming unbound authority; active native provider/Go host calls still require their own timeout or cancellation support.
- JavaScript callbacks and plugin commands that arrive while startup or a manual reload is still loading scripts are dropped instead of queueing behind the busy loop until the 10-second callback deadline expires. Each plugin and callback kind logs one WARN for its first dropped event and stays silent afterwards; a final WARN summarises the per-plugin counts when loading ends, and nothing is logged when nothing was dropped. Plugins that have not registered yet cannot be recognised, so their commands remain silent. Callbacks raised by a script from inside its own runtime still run, and delivery, including `OnLoad`, resumes as soon as script loading ends.
- Outbox claims isolate confirmed ciphertext/format corruption, atomically settle the operation and outcome event, and advance the lane. Previously dispatched corrupt items remain ambiguous; temporary key failures remain retryable infrastructure errors rather than being misclassified as corrupted data.
- Custom CoC rules execute on their registered runtime generation and plugin realm. Registration and lookup are synchronized, registrations retain immutable copies, and reload drains old runtimes before clearing registries. `CocExtraRulesSnapshot()` replaces direct access to the mutable `CocExtraRules` map and exposes metadata only.

- Sandbox replies no longer disappear when multiple pages poll or an HTTP response is lost. `/dice/recentMessage` now returns `{cursor, messages, truncated}` and reads a bounded 256-message history without consuming it. Each page advances its own cursor only after displaying the batch; slow polls are single-flight. New pages start at the current tail, and expired/restarted streams report a visible gap instead of silently dropping replies.
- Replies from UI and legacy adapters, including their outgoing-message hooks, now finish on the command's execution path rather than escaping through the asynchronous panic handler and racing execution-context release.

- Callback persistence now permits literal `$t` references in player templates and other text, including `.sn coc`; request-local attribute keys remain excluded at the typed attribute boundary. Invalid collected events report their aggregate, event index/type, and rejection category without logging payload contents.

- Durable group exits no longer depend on a legacy adapter: API farewell and quit effects commit atomically in FIFO order, callback exits retain their transaction identity and only remove canonical/local membership after callback CAS succeeds, recurring automatic exits use fresh identities, and rejected API exits preserve local membership without sending success notices.

- Ordinary event commits no longer scan historical encryption-root references or open unused historical key material. Explicit `--verify-event-store` audits remain complete, and current-record authentication and publication fences remain enforced.

- Callback lease renewal continues through commit-fence waiting, then hands the final version to a bounded terminal commit. Canceled fence waits don't leave lock-wait goroutines or submit late Host mutations.

- SQLite connection replacements retain the configured WAL, foreign-key, busy-timeout and synchronization settings. Projection payload-presence upgrades now add, repair and mark completion atomically, recover interrupted older upgrades once, and preserve empty BLOBs.
- Large legacy SQLite queue upgrades now apply the query timeout per SQL statement instead of to the whole startup migration, walk scheduling-version indexes without rescanning migrated prefixes, report bounded stage/progress metadata, and remain resumable after caller cancellation.

- OneBot failures retain redacted action, status, return code and provider cause in durable outcome events and the separate queue failure log. Unknown post-dispatch outcomes only retry provider-idempotent effects. Database initialization errors retain safe error classes and causes instead of discarding the original failure.

- Standalone outbox acceptance now preserves its privacy subject. Privacy resolution refreshes affected lane heads in the same transaction, and claims reject stale terminal or future-due candidates rather than reviving or sending them early.

- `.ob` and `.ob exit` now use the durable group-card path without requiring a legacy Adapter. Delegated player state, card updates and replies share the callback transaction, including target-state recovery and version checks. Durable replies execute on the owning callback, and execution state is released only after all mutations have been collected.

- Sensitive plugin configuration keeps its defaults and explicit values in a separate encrypted namespace. Definition and value changes commit atomically; opaque public storage keys remain unchanged, and typed getter errors include safe configuration identity and can be caught by JavaScript.

- Normal inbound callbacks refresh group information on demand under the existing cooldown, without an extra background ticker. Validated OneBot/Milky observations update Core caches without racing callbacks, empty inbound names don't erase observed names, and omitted provider counts preserve previously known values.

- Failed and ambiguous inbox/outbox items are isolated rather than permanently blocking later messages in the same lane. Expired unsent outbox items reach a terminal failure instead of being claimed in a tight loop; unknown provider outcomes are retained without automatic replay. Queue failures are written to the separately rotated `data/queue-failures.log`.

- Outbox expiry and explicit terminal resolutions now settle the effect, associated operation, outcome event, and story-log intent in one transaction. Operator resolutions preserve the operator identity/reason and the causation chain instead of leaving the operation at its previous ambiguous outcome.

- Legacy endpoint imports now preserve event envelope command/correlation metadata, account identity, display names, and authoritative `endpoint_info` historical counters with `NULL`-safe reads. Endpoint replay narrowly recognizes the early importer's deterministic wrapper metadata, so those already-published streams can load without weakening arbitrary mismatch rejection. Normal startup idempotently appends a metadata-repair event for databases produced by the early importer, without replacing newer non-empty account data; import readback identifies the mismatched field instead of returning a bare validation sentinel, and publication remains isolated until the complete candidate validates and is atomically activated.

- Durable OneBot outbound text now expands CQ and Seal resource codes before provider delivery, including `data/...` local assets, generic CQ segments, and the custom `[CQ:recall]` control syntax with explicit, sent-message, and delayed recall targets. Signed non-zero OneBot message IDs are preserved for send acknowledgements, edits, and recalls. Local asset resolution remains confined to `data/` and documented in [OneBot outbound message codes](docs/onebot-message-codes.md).

- JavaScript extension files now execute in file-local CommonJS scope, so separate plugins may reuse top-level `let`/`const` names. Imported legacy extension identities are adopted once and later same-source version changes remain durable, while cross-source replacement is still rejected with the original contextual error.

- WebUI and the base runtime now become available without waiting for every optional JavaScript extension to finish loading; extension progress remains observable while loading continues in the background. JavaScript cron scheduling is initialized on demand, stays goroutine-free for empty instances, and stops in-flight jobs before closing their JS runtimes.

- Process shutdown uses one 30-second deadline for JavaScript loads, cron jobs, callbacks, event workers and the endpoint supervisor. Concurrent cleanup callers join the same stop operation; late worker/JS admission is rejected, and a timeout doesn't close a database that running callbacks may still use.

- Concurrent relogin/disable commands no longer turn obsolete lifecycle observations into ambiguous workers. Old-worker cleanup retains its own fence, so a replacement operation stays pending until its own connection completes.

- Legacy imports now read instance databases from their copied snapshot paths when `dataDir` is installation-relative (for example, `data/default`) or absolute; remote SQL snapshots use the same rebased layout.

- Legacy imports now normalize historical `NULL` group timestamps, optional player fields, and optional story-log scalar fields across SQLite and remote SQL snapshots; zero-valued imported session timestamps are preserved instead of being replaced by ORM auto-timestamps. Unaddressable hidden attribute placeholders are ignored only when both metadata and the attribute dictionary are empty; populated rows without an identity still fail closed. Validation failures retain safe stage, table, and row context instead of reporting only `eventsourcing: validation failed`.

- Legacy archives above one million semantic records no longer fail the fixed manifest ceiling. Full source and target record sets are still canonically hashed and compared; when the canonical bytes exceed the readiness storage bound, only the matching SHA-256 digests are persisted.

- Legacy BuntDB plugin storage now preserves zero-length opaque keys instead of quarantining the whole import. Large imports use a `(dice_hmac, identity_hmac)` keyset index for story-log readback, batch-load receipt/session/resource lookups, reuse privacy and encryption key material, and verify events, credentials, and plugin values through one paged consistent transaction instead of per-record transactions; local publication candidates use reduced SQLite durability only while isolated, then restore `synchronous=FULL`, checkpoint, reopen, and verify before atomic publication. Any handle-close error after successful activation is reported as a cleanup warning instead of falsely quarantining an already-active import.

- Legacy story-log imports now derive cryptographic material once per bounded batch, bulk-write encrypted archive rows and import markers, and stream authenticated target readback instead of retaining a second million-row receipt set. SQLite verification follows physical insertion order and contiguous resource ranges instead of hash-order random seeks. Full verification of the committed candidate database remains mandatory before atomic activation.

- Normal startup no longer loads or re-hashes the multi-megabyte readiness manifest or scans every encrypted row on each store operation. Exhaustive event-store verification is opt-in with `--verify-event-store`; required metadata and per-record AES-GCM authentication remain enforced. Encryption-root admission is read once per publication-fenced transaction, so revocation remains immediate without repeating a full readiness query for every encrypted row; fresh-store commits read only their two marker columns. Durable attributes are restored in bounded 5,000-state batches with paged secret reads and one cached encryption-root load per batch instead of per-attribute transactions. Callback/effect processing keeps all four workers per queue, wakes immediately for committed work, and uses polling backoff only as an idle/retry fallback. Non-default random generators are initialized only when selected, preserving every mode while avoiding their 32 MiB entropy workspace in ordinary PCG instances. Mutex and block profiling are now off unless explicitly enabled.

- Saving custom text now preserves whitespace and line breaks in every entry of the submitted category, including entries that were not edited.

- Disabling a JavaScript plugin now persists across EventStore saves and reloads.

- The endpoint management list now omits completed deletion tombstones while keeping removals visible until completion; endpoint-by-ID reads and durable deletion history are preserved.

- Explicit disable and enabled-endpoint removal now persist successful completion when the runtime stop finishes, while stale worker-fence callbacks remain rejected.

- QuickJS `onMessagePreprocess` callbacks return provider-neutral values consumed on their owning loop. Callback exceptions remain observable; durable callback failures discard collected mutations rather than publishing partial plugin writes.

- QuickJS Host ABI 1.1 balances HostRef proxies, removes owner-bound method registry entries with their final proxy, and accepts matching HostRef releases through provider destruction; message-preprocess parsing matches Goja own-property behavior and reports getter exceptions.
